## Supplemental authoritative material

- [OWASP API Security Top 10, 2023 edition](https://api-security.owasp.org/editions/2023/en/0x11-t10/): read the risk overview and linked individual risk pages. Individual links accompany the test prompts in api-checks.md. The operational examples are original synthesis, not course quotations.
- [OWASP: What's Next for DevSecOps](https://api-security.owasp.org/editions/2023/en/0xb1-next-devsecops/): threat-model-led testing, SDLC fit, accuracy, and useful findings.
- [NIST SP 800-218, SSDF v1.1](https://csrc.nist.gov/pubs/sp/800/218/final): read the publication overview and abstract. It supports integrating secure development practices into SDLCs and addressing vulnerability root causes. Do not imply the full standard was audited or that the skill implements every practice.
- [NIST SP 800-207, Zero Trust Architecture](https://csrc.nist.gov/pubs/sp/800/207/final): read the publication overview and abstract, which rejects implicit trust based only on network location or asset ownership. The internal-API review prompt is an application of that principle, not a full zero-trust architecture assessment.
- [GitHub Actions secure use reference](https://docs.github.com/en/actions/reference/security/secure-use): read current guidance on workflow permissions, untrusted content, dependencies, secrets, federation, and runner isolation. Reverify details when implementing platform-specific configuration.
- [Sigstore verification](https://docs.sigstore.dev/cosign/verifying/verify/) and [GitHub artifact attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations): read artifact identity, signer/issuer, digest, and provenance-verification guidance. These supplement the course's less precise description of hashes and signatures. No signing infrastructure was configured.
